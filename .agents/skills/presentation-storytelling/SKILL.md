# Presentation Storytelling Skill

## 1. Core Principles
- **Minto Pyramid Structure:** State the executive answer or conclusion first, followed by supporting pillars, evidence, and actionable next steps.
  - Proposals: Context ➔ Requirements ➔ Integrated Solution ➔ Proof / Product Depth ➔ Assessment ➔ Migration ➔ Integration ➔ Phased Roadmap ➔ Commercial Framework & Terms.
- **One Message Per Slide:** Every slide proves exactly one conclusion. If a slide attempts to prove two separate conclusions, split it.
- **Action Titles (≤ 9 words):** Titles must be active statements of the conclusion, never passive topic labels.
  - *Incorrect:* "Workstreams Overview", "ERP Integration Details".
  - *Correct:* "Four connected workstreams around Odoo", "Automated payroll and time-tracking integration".
- **The Single-Allocation Rule:** Every fact, metric, and scope description must be allocated to **exactly one slide**. Zero cross-slide repetition. Do not duplicate Workstream definitions on the Cover slide if they belong on the Solution Architecture slide.
- **Banned Words & Unsubstantiated Superlatives:** Never use fluff adjectives.
  - Banned: *"world-class"*, *"revolutionary"*, *"seamless"*, *"best-in-class"*, *"game-changer"*, *"cutting-edge"*, *"unparalleled"*, *"synergistic"*.

## 2. Word Budgets (Enforced in Code)
- **Cover Slide:** ≤ 50 words.
- **Standard Slide Target:** ≤ 120 words (Hard Cap: 160 words).
- **Dense Reference Slides (Commercials, Terms):** ≤ 200 words.
- **Bullet Points:** ≤ 12 words per bullet.
- **Card Descriptions:** ≤ 3 lines (≤ 25 words).
- **Containers:** ≤ 6 items maximum per container.

## 3. Speaker Notes Separation
- The slide visual carries the strategic structure, metrics, and relationships.
- Explanatory context, methodologies, technical caveats, and source attributions belong in the **speaker notes**, not on the visual canvas.
